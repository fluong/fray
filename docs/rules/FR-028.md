# Database access is scoped to one instance

| | |
|---|---|
| **ID** | FR-028 |
| **Severity** | medium |
| **STRIDE** | Elevation of privilege |
| **Category** | Identity |
| **Platforms** | AWS, Google Cloud |

Requires Action v0.31.0 or later.

## The risk

Database access granted at project or account scope

## Why it matters

A grant wider than one database lets the caller connect to every instance in that scope, not only the database this flow uses.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | The caller can reach every relational database in the project or account. |
| **Mitigated** | The caller can reach only this database. |
| **Unverified** | Fray only evaluates this rule when it can see how wide the grant is, so it is never unverified. |

## How to fix

Grant connect (or Cloud SQL client) on the individual instance, not on the project or account. On Google Cloud, use an IAM Condition on resource.name for that instance (see Cloud SQL IAM Conditions docs).

- **AWS** (`aws_iam_policy`): scope `rds-db:connect` to one `arn:aws:rds-db:<region>:<account>:dbuser:<dbi-resource-id>/<db-user>` ARN, and `rds-data:*` to one cluster ARN, instead of `"*"`.
- **Google Cloud** (`google_project_iam_member`): add a `condition` block with `resource.name == "projects/<project>/instances/<instance>"` to the `roles/cloudsql.client` (or `cloudsql.instanceUser`) binding; don't grant `roles/cloudsql.admin` project-wide.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-028
    address: aws_ecs_service.app -> aws_db_instance.main unknown
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

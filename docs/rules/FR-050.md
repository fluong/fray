# Secret is not shared through its resource policy

| | |
|---|---|
| **ID** | FR-050 |
| **Severity** | medium |
| **STRIDE** | Information disclosure, Elevation of privilege |
| **Category** | Exposure |
| **Platforms** | AWS |

Requires Action v0.37.0 or later.

Severity is **high** when the policy allows any principal. Severity is **medium** when the policy allows only specific principals outside this account.

## The risk

Secret resource policy grants access outside the account

## Why it matters

Secrets Manager resource policies can grant `GetSecretValue` and related actions without going through IAM identity policies modeled as flows. A policy that allows `*` or principals in other accounts widens who can read the secret if they satisfy the policy's conditions.

## How Fray evaluates it

Fray evaluates this rule on every Secrets Manager secret in the plan. A secret with no resource policy is mitigated.

| Result | Meaning |
|---|---|
| **Open** | The resource policy allows any principal without a restricting condition, or allows a principal in another AWS account. |
| **Mitigated** | There is no resource policy, or the policy grants only principals in this account, or access is restricted by organization, account, VPC, or source conditions that Fray can verify. Setting `block_public_policy = true` on the secret mitigates the any-principal part of the evaluation; cross-account grants are still read from the policy when known. |
| **Unverified** | The policy could not be read at plan time, a Deny with conditions makes the effective access unclear, or the owning account is not known. |

## How to fix

Replace broad principals with explicit ARNs and add conditions that tie access to your organization or account. Enable block public policy when anonymous or broad resource policies must not apply.

- **AWS** (`aws_secretsmanager_secret_policy`): Restrict `Principal` to specific IAM roles or accounts instead of `"*"`.

```hcl
resource "aws_secretsmanager_secret_policy" "example" {
  secret_arn = aws_secretsmanager_secret.example.arn
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid       = "AllowAppRole"
      Effect    = "Allow"
      Principal = { AWS = aws_iam_role.app.arn }
      Action    = ["secretsmanager:GetSecretValue"]
      Resource  = aws_secretsmanager_secret.example.arn
    }]
  })
}
```

- **AWS** (`aws_secretsmanager_secret`): Block resource policies that grant public access.

```hcl
resource "aws_secretsmanager_secret" "example" {
  name                 = "example/app"
  block_public_policy  = true
  recovery_window_in_days = 30
}
```

- **AWS** (`aws_secretsmanager_secret_policy`): When you must allow cross-account access, add `aws:SourceAccount` or `aws:PrincipalOrgID` so only your org or account can use the grant.

```hcl
resource "aws_secretsmanager_secret_policy" "example" {
  secret_arn = aws_secretsmanager_secret.example.arn
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid       = "AllowPartnerAccount"
      Effect    = "Allow"
      Principal = { AWS = "arn:aws:iam::111122223333:root" }
      Action    = ["secretsmanager:GetSecretValue"]
      Resource  = aws_secretsmanager_secret.example.arn
      Condition = {
        StringEquals = {
          "aws:SourceAccount" = "111122223333"
        }
      }
    }]
  })
}
```

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-050
    address: aws_secretsmanager_secret.app
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

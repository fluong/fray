# Object storage does not use ACLs

| | |
|---|---|
| **ID** | FR-024 |
| **Severity** | medium |
| **STRIDE** | Elevation of privilege |
| **Category** | Identity |
| **Platforms** | AWS, Google Cloud, Cloudflare |

Available since Fray's first public release

## The risk

Object ACLs can grant access that bucket policy does not show

## Why it matters

An object ACL can grant access that bucket IAM does not show.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | Object ACLs can still grant access outside bucket policy. |
| **Mitigated** | Object ACLs are disabled; only bucket policy grants access. |
| **Unverified** | Fray could not tell whether object ACLs are disabled. |

## How to fix

Disable object ACLs so only bucket IAM grants access.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-024
    address: aws_s3_bucket.assets
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

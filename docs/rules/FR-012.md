# Object storage cannot be destroyed by the tool

| | |
|---|---|
| **ID** | FR-012 |
| **Severity** | medium |
| **STRIDE** | Tampering, Denial of service |
| **Category** | Resilience |
| **Platforms** | AWS, Google Cloud, Cloudflare |

Available since Fray's first public release

## The risk

Object storage can be destroyed by the infrastructure tool

## Why it matters

Destroying the bucket removes the stored objects, including any archive.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | Deletion protection is off, so the bucket can be deleted. |
| **Mitigated** | Deletion protection is on. |
| **Unverified** | Fray could not tell whether deletion protection is on. |

## How to fix

Block destroy of the bucket in the infrastructure tool.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-012
    address: aws_s3_bucket.assets
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

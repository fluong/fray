# Relational database is not directly reachable from the internet

| | |
|---|---|
| **ID** | FR-029 |
| **Severity** | high |
| **STRIDE** | Information disclosure |
| **Category** | Exposure |
| **Platforms** | AWS, Google Cloud |

Available since 2026-10-11

For full results, use Fray Action v0.13.0 or later.

## The risk

Relational database is publicly accessible and its network access rules (security groups, authorized networks) are open to the internet

## Why it matters

A database that is both publicly accessible and open to the internet on its listen port can be reached without going through the application tier. Keeping the database off public addresses, reachable only through your application, is the intended control. A database that is only reachable through your application is not flagged.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | The database has a public address and its network access rules allow the internet on the database port. |
| **Mitigated** | The database has no public address, or its network access rules only admit known sources. |
| **Unverified** | Fray could not tell whether the database has a public address or what its network access rules allow. |

## How to fix

Make the database not publicly accessible, or restrict its network access rules (security groups, authorized networks) to known application sources (not the internet).

- **AWS** (`aws_db_instance`): set `publicly_accessible = false`, or restrict the DB security group ingress to the app security group (no `0.0.0.0/0` / `::/0` on the DB port).
- **Google Cloud** (`google_sql_database_instance`): Disable public IP (`settings.ip_configuration.ipv4_enabled = false`) and use private IP or the Cloud SQL connectors; if a public IP is needed, do not add authorized networks wider than necessary, and never `0.0.0.0/0`.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-029
    address: aws_db_instance.main
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

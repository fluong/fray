# NoSQL table access is scoped to that table

| | |
|---|---|
| **ID** | FR-039 |
| **Severity** | medium |
| **STRIDE** | Elevation of privilege |
| **Category** | Identity |
| **Platforms** | AWS |

For flow rules, Platforms lists the providers whose parsers produce the attributes this rule reads; the rule is evaluated on every matching flow.

Requires Action v0.34.0 or later.

## The risk

NoSQL access granted at account scope

## Why it matters

A grant wider than one DynamoDB table lets the caller read or write every table in the account, not only the table this flow uses.

## How Fray evaluates it

Fray evaluates this rule only on compute-to-table flows where the target table is identified. Each table named in the IAM policy gets its own flow. An account-wide grant with no named table creates a flow only when exactly one DynamoDB table is in the plan.

Callers include ECS tasks, Lambda functions, EC2 instances, Auto Scaling groups, and EKS node groups.

| Result | Meaning |
|---|---|
| **Open** | The caller can reach every DynamoDB table in the account. |
| **Mitigated** | The caller can reach only this table. |
| **Unverified** | Fray only evaluates this rule when it can see how wide the grant is, so it is never unverified. |

## How to fix

Scope DynamoDB actions to the table ARN (and that table's index or stream ARNs), not to `"*"` or table-name wildcards.

- **AWS** (`aws_iam_policy_document`): scope DynamoDB actions to `arn:aws:dynamodb:<region>:<account>:table/<name>` (and that table's index/stream ARNs), not `"*"`.
- **AWS** (`aws_iam_policy`): scope DynamoDB actions to one table ARN prefix, not `"*"`.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-039
    address: aws_ecs_service.app -> aws_dynamodb_table.sessions unknown
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

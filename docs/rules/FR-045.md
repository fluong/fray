# Message queue access is scoped to that queue or topic

| | |
|---|---|
| **ID** | FR-045 |
| **Severity** | medium |
| **STRIDE** | Elevation of privilege |
| **Category** | Identity |
| **Platforms** | AWS |

For flow rules, Platforms lists the providers whose parsers produce the attributes this rule reads; the rule is evaluated on every matching flow.

Requires Action v0.38.0 or later.

## The risk

Message queue access granted at account scope

## Why it matters

A grant wider than one SQS queue or SNS topic lets the caller publish to or consume from every queue and topic in the account, not only the queue or topic this flow uses.

## How Fray evaluates it

Fray evaluates this rule on compute-to-queue flows where the target is a `message_queue` element (SQS queues and SNS topics). Fray infers scope from IAM policies attached to the caller: SQS actions such as `sqs:SendMessage`, `sqs:ReceiveMessage`, `sqs:DeleteMessage`, and `sqs:GetQueueAttributes`, and SNS actions such as `sns:Publish`. Each queue or topic named in the policy gets its own flow. An account-wide grant with no named queue or topic creates a flow only when exactly one queue or topic of that kind is in the plan.

Callers include ECS tasks, Lambda functions, EC2 instances, Auto Scaling groups, and EKS node groups.

| Result | Meaning |
|---|---|
| **Open** | The caller can reach every SQS queue or SNS topic in the account. |
| **Mitigated** | The caller can reach only this queue or topic. |
| **Unverified** | Fray only evaluates this rule when it can see how wide the grant is, so it is never unverified. |

## How to fix

Scope SQS and SNS actions to the queue or topic ARN, not to `"*"` or account-wide resource patterns.

- **AWS** (`aws_iam_policy_document`): scope SQS actions to `arn:aws:sqs:<region>:<account>:<queue-name>` and SNS publish to `arn:aws:sns:<region>:<account>:<topic-name>`, not `"*"`.
- **AWS** (`aws_iam_policy`): scope SQS and SNS actions to one queue or topic ARN prefix, not `"*"`.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-045
    address: aws_lambda_function.worker -> aws_sqs_queue.jobs unknown
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

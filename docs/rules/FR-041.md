# Cache accepts traffic only from restricted networks

| | |
|---|---|
| **ID** | FR-041 |
| **Severity** | low |
| **STRIDE** | Information disclosure |
| **Category** | Exposure |
| **Platforms** | AWS |

Requires Action v0.35.0 or later.

## The risk

Cache accepts traffic from a wide network range

## Why it matters

ElastiCache clusters are reachable only inside the VPC. A security group that admits a very wide CIDR (for example `10.0.0.0/8` or `0.0.0.0/0`) lets more of the network reach the cache than a tight source list. This is not internet exposure — there is no public ElastiCache endpoint — but it widens who inside or peered into the VPC can talk to the cache.

## How Fray evaluates it

Fray evaluates this rule only on ElastiCache elements (`kind = cache`) with infrastructure provenance.

| Result | Meaning |
|---|---|
| **Open** | A security group attached to the cache allows ingress from a wide CIDR. |
| **Mitigated** | The cache accepts traffic only from restricted networks (specific, non-wide sources). |
| **Unverified** | Fray could not read the cache security groups or their CIDR rules. |

## How to fix

Restrict ElastiCache security group ingress to the application security groups or subnets that need the cache, not large RFC1918 blocks or `0.0.0.0/0`.

- **AWS** (`aws_security_group` on the cache cluster or replication group): Replace wide `cidr_blocks` / `ipv6_cidr_blocks` on the cache port with `security_groups` referencing the app tier.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-041
    address: aws_elasticache_replication_group.sessions
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

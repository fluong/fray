# Container image is pinned by digest

| | |
|---|---|
| **ID** | FR-005 |
| **Severity** | medium |
| **STRIDE** | Tampering |
| **Category** | Supply chain |
| **Platforms** | AWS, Google Cloud |

Available since Fray's first public release

## The risk

Container image can be replaced without a review

## Why it matters

A mutable image tag can be moved in the registry, so a later start runs different code than the one reviewed.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | The service starts from a mutable image tag. |
| **Mitigated** | The service image is pinned by digest. |
| **Unverified** | Fray could not tell whether the image is pinned by digest. |

## How to fix

Deploy the image by digest.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-005
    address: aws_ecs_service.app
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

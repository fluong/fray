# Secrets are rotated

| | |
|---|---|
| **ID** | FR-009 |
| **Severity** | low |
| **STRIDE** | Information disclosure |
| **Category** | Identity |
| **Platforms** | AWS, Google Cloud |

Available since Fray's first public release

## The risk

Secret is never rotated

## Why it matters

A credential with no rotation stays valid indefinitely after it leaks.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | Automatic rotation is not configured for the secret. |
| **Mitigated** | Rotation is configured on the secret. |
| **Unverified** | Fray could not tell whether rotation is configured. |

## How to fix

Configure a rotation schedule on the secret.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-009
    address: aws_s3_bucket.assets
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

# Object storage is not public

| | |
|---|---|
| **ID** | FR-010 |
| **Severity** | high |
| **STRIDE** | Information disclosure |
| **Category** | Exposure |
| **Platforms** | AWS, Google Cloud, Cloudflare |

Available since Fray's first public release

## The risk

Objects are readable by anyone who can name them

## Why it matters

Objects in a public bucket are readable by anyone who can name them.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | Anyone on the internet can read objects in the bucket. |
| **Mitigated** | The bucket is private. |
| **Unverified** | Fray could not tell whether the bucket is public. |

## How to fix

Keep the bucket private. Do not grant public read.

- **Cloudflare** (`cloudflare_r2_managed_domain`): Remove or disable the managed domain. To share specific objects, use presigned URLs.
  
  This enables a public r2.dev URL on the bucket. Anyone who knows an object name can read it without credentials.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-010
    address: aws_s3_bucket.uploads
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

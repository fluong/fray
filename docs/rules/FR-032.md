# Object storage access is scoped to one resource

| | |
|---|---|
| **ID** | FR-032 |
| **Severity** | medium |
| **STRIDE** | Elevation of privilege |
| **Category** | Identity |
| **Platforms** | AWS, Google Cloud, Cloudflare |

Available since 2026-10-11

## The risk

Object storage access granted at project or account scope

## Why it matters

A grant wider than one bucket lets the caller read or write objects in every store in that scope, not only the bucket this flow uses.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | The caller can access every object store in the project or account. |
| **Mitigated** | The caller can access only this bucket. |
| **Unverified** | Fray only evaluates this rule when it can see how wide the grant is, so it is never unverified. |

## How to fix

Grant access on the individual bucket, not on the project or account.

- **AWS** (`aws_iam_policy`): scope S3 actions to the bucket ARN and object ARN prefix in `Resource`, not `"*"`.
- **AWS** (`aws_iam_policy_document`): scope S3 actions to the bucket ARN and object ARN prefix in `Resource`, not `"*"`.
- **Google Cloud** (`google_project_iam_member`): grant storage roles on each bucket with `google_storage_bucket_iam_member`, not on the project.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-032
    address: aws_ecs_service.app -> aws_s3_bucket.uploads unknown
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

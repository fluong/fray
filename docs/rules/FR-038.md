# Relational database is protected from console and API deletion

| | |
|---|---|
| **ID** | FR-038 |
| **Severity** | medium |
| **STRIDE** | Tampering, Denial of service |
| **Category** | Resilience |
| **Platforms** | AWS, Google Cloud |

Requires Action v0.28.0 or later.

## The risk

Relational database can be deleted through the cloud console or API

## Why it matters

FR-033 blocks destroy through the infrastructure tool. Operators can still
delete the live database through the cloud console or API unless the
provider's deletion-protection flag is on. That gap loses the data and
breaks every workload that depends on it.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | Provider deletion protection is off, so the database can be deleted outside Terraform. |
| **Mitigated** | Provider deletion protection is on. |
| **Unverified** | Fray could not tell whether provider deletion protection is on. |

## How to fix

Enable the provider setting that refuses console and API deletion. This is
separate from `lifecycle.prevent_destroy` and (on Cloud SQL) from Terraform's
`deletion_protection` argument, which only block the infrastructure tool.

- **AWS** (`aws_db_instance`): set `deletion_protection = true`.
- **AWS** (`aws_rds_cluster`): set `deletion_protection = true`.
- **Google Cloud** (`google_sql_database_instance`): set
  `settings.deletion_protection_enabled = true`.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-038
    address: aws_db_instance.main
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

# Traffic that crosses a trust boundary is encrypted

| | |
|---|---|
| **ID** | FR-026 |
| **Severity** | medium |
| **STRIDE** | Information disclosure |
| **Category** | Encryption |
| **Platforms** | AWS, Google Cloud |

Available since Fray's first public release

## The risk

Traffic crosses a trust boundary unencrypted

## Why it matters

A flow that crosses a trust boundary can be read by whoever sits on the other side. TLS passes. Plaintext is open. Unknown transport is unverified. A network crossing is high. Any other crossing stays medium.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | Traffic crosses a trust boundary without encryption. |
| **Mitigated** | Traffic that crosses a trust boundary uses TLS. |
| **Unverified** | Fray could not tell whether the crossing uses TLS. |

## How to fix

Encrypt this flow in transit.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-026
    address: aws_iam_role.app -> aws_secretsmanager_secret.db credentials
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

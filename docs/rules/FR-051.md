# REST API is not shared through its resource policy

| | |
|---|---|
| **ID** | FR-051 |
| **Severity** | medium |
| **STRIDE** | Information disclosure, Elevation of privilege |
| **Category** | Exposure |
| **Platforms** | AWS |

Requires Action v0.40.0 or later.

Severity is **high** when the policy allows any principal. Severity is **medium** when the policy allows only specific principals outside this account.

## The risk

REST API Gateway resource policy grants `execute-api:Invoke` outside your account.

## Why it matters

Amazon API Gateway REST APIs can attach a resource policy that controls who may invoke the API, independent of method authorization on individual routes. A policy that allows `*` or principals in other AWS accounts widens who can call the API if they satisfy the policy's conditions.

Method-level authorization (for example `AWS_IAM` or Cognito on `aws_api_gateway_method`) is evaluated separately on the public entry flow by **FR-001**. A restrictive resource policy does not replace method auth, and a public method does not override a restrictive resource policy.

**PRIVATE** APIs (`endpoint_configuration.types = PRIVATE`) are not reachable from the public internet; Fray still evaluates the resource policy on the API element because invoke grants may be wider than the network path.

## How Fray evaluates it

Fray evaluates this rule on every REST API Gateway (`aws_api_gateway_rest_api`) in the plan. HTTP APIs (`aws_apigatewayv2_api`) do not use this resource policy model and are out of scope for **FR-051**.

| Result | Meaning |
|---|---|
| **Open** | The resource policy allows any principal without a fully restricting condition, or allows a principal in another AWS account. |
| **Mitigated** | There is no resource policy, or the policy grants only principals in this account, or access is restricted by VPC endpoint, VPC, or organization conditions that Fray can verify. |
| **Unverified** | The policy could not be read at plan time, a Deny with conditions makes the effective access unclear, or the owning account is not known. |

An IP allowlist on a Deny limits anonymous internet access but does not, by itself, block other AWS accounts when the Allow still permits them; Fray then reports **Open** at medium severity.

## How to fix

Replace broad principals with explicit ARNs. When the API should be reachable only through a VPC endpoint, add a Deny for principals outside your VPC endpoint or VPC, or restrict the Allow to your organization.

- **AWS** (`aws_api_gateway_rest_api` or `aws_api_gateway_rest_api_policy`): Restrict `Principal` to principals in your own account instead of `"*"`.

```hcl
resource "aws_api_gateway_rest_api_policy" "example" {
  rest_api_id = aws_api_gateway_rest_api.example.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid       = "AllowInternalInvoke"
      Effect    = "Allow"
      Principal = { AWS = "arn:aws:iam::111122223333:role/internal-invoke" }
      Action    = "execute-api:Invoke"
      Resource  = "${aws_api_gateway_rest_api.example.execution_arn}/*"
    }]
  })
}
```

- **AWS**: When invoke must stay inside a VPC endpoint, deny callers that do not use that endpoint.

```hcl
resource "aws_api_gateway_rest_api_policy" "internal" {
  rest_api_id = aws_api_gateway_rest_api.example.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect    = "Allow"
        Principal = "*"
        Action    = "execute-api:Invoke"
        Resource  = "${aws_api_gateway_rest_api.example.execution_arn}/*"
      },
      {
        Effect    = "Deny"
        Principal = "*"
        Action    = "execute-api:Invoke"
        Resource  = "${aws_api_gateway_rest_api.example.execution_arn}/*"
        Condition = {
          StringNotEquals = {
            "aws:SourceVpce" = aws_vpc_endpoint.execute_api.id
          }
        }
      },
    ]
  })
}
```

## Waivers

Waive when a broader invoke policy is deliberate and tracked.

```yaml
waivers:
  - id: partner-api-invoke
    rule: FR-051
    target: aws_api_gateway_rest_api.partner
    reason: Documented cross-account partner integration
    expires: 2027-01-01
```

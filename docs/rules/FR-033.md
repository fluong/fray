# Relational database cannot be destroyed by the tool

| | |
|---|---|
| **ID** | FR-033 |
| **Severity** | medium |
| **STRIDE** | Tampering, Denial of service |
| **Category** | Resilience |
| **Platforms** | AWS, Google Cloud |

Available since 2026-10-11

## The risk

Relational database can be destroyed by the infrastructure tool

## Why it matters

Destroying the database deletes the live data and breaks every workload that depends on it.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | Deletion protection is off, so the database can be deleted. |
| **Mitigated** | Destroy is blocked: provider deletion protection is on, or the infrastructure tool is told not to destroy the database (lifecycle.prevent_destroy; on Cloud SQL the Terraform deletion_protection argument, which defaults to true). |
| **Unverified** | Fray could not tell whether deletion protection is on. |

## How to fix

Block destroy of the database in the infrastructure tool and enable the provider's deletion-protection setting where available.

- **AWS** (`aws_db_instance`): set `deletion_protection = true`, or set `lifecycle.prevent_destroy`.
- **Google Cloud** (`google_sql_database_instance`): Keep the Terraform `deletion_protection` argument set to true (the default) or set `lifecycle.prevent_destroy`. To also block deletion through the console or API, set `settings.deletion_protection_enabled = true`.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-033
    address: aws_db_instance.main
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

# Relational database cannot be destroyed by the tool

| | |
|---|---|
| **ID** | FR-033 |
| **Severity** | medium |
| **STRIDE** | Tampering, Denial of service |
| **Category** | Resilience |
| **Platforms** | AWS |

Available since 2026-10-11

## The risk

Relational database can be destroyed by the infrastructure tool

## Why it matters

Destroying the database deletes the live data and breaks every workload that depends on it.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | Deletion protection is off, so the database can be deleted. |
| **Mitigated** | Deletion protection is on. |
| **Unverified** | Fray could not tell whether deletion protection is on. |

## How to fix

Block destroy of the database in the infrastructure tool.

- **AWS** (`aws_db_instance`): set `deletion_protection = true`, or set `lifecycle.prevent_destroy`.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-033
    address: aws_db_instance.main
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

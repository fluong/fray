# Network entry is not anonymous

| | |
|---|---|
| **ID** | FR-001 |
| **Severity** | medium |
| **STRIDE** | Spoofing |
| **Category** | Exposure |
| **Platforms** | AWS, Google Cloud |

Available since Fray's first public release

## The risk

Anyone on the internet can call this service

## Why it matters

A flow that crosses into the trusted side of a network boundary can be called by whoever can route to it. Public authorization means no caller identity is required at the edge.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | The network entry accepts callers with no identity. |
| **Mitigated** | The network entry requires a caller identity. An entry that requires caller identity (IAM signature, JWT, Cognito, OIDC) counts as mitigated even though the set of permitted callers is not known. |
| **Unverified** | Fray could not tell whether the entry requires a caller identity. With Fray Action v0.17.0 or later, API Gateway entries that use custom (Lambda) authorizers or are defined by an OpenAPI body are reported as unverified. |

## How to fix

Require a caller identity on this flow. Do not grant it to the public.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-001
    address: signal:network_ingress:0.0.0.0/0 -> aws_lb.main unknown
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

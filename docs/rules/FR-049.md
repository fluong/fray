# Storage bucket is not shared through its bucket policy

| | |
|---|---|
| **ID** | FR-049 |
| **Severity** | medium |
| **STRIDE** | Information disclosure, Elevation of privilege |
| **Category** | Exposure |
| **Platforms** | AWS |

Requires Action v0.37.0 or later.

Severity is **high** when the policy allows any principal. Severity is **medium** when the policy allows only specific principals outside this account.

## The risk

Storage bucket policy grants access outside the account

## Why it matters

S3 bucket policies can grant object access without going through IAM roles in your account. A policy that allows `*` or principals in other accounts lets callers outside your workload boundary read or write objects if they satisfy the policy's conditions.

Public access through object ACLs or Block Public Access settings is covered by **FR-010**. Fray may report **FR-010** and **FR-049** on the same bucket when both apply; they address different controls and causes.

## How Fray evaluates it

Fray evaluates this rule on every S3 bucket in the plan. A bucket with no bucket policy is mitigated.

| Result | Meaning |
|---|---|
| **Open** | The bucket policy allows any principal without a restricting condition, or allows a principal in another AWS account. |
| **Mitigated** | There is no bucket policy, or the policy grants only principals in this account, or access is restricted by organization, account, VPC, or source conditions that Fray can verify. Block Public Access on the bucket, or account-level Block Public Access on the same provider configuration with public buckets restricted, mitigates the any-principal part of the evaluation. |
| **Unverified** | The policy could not be read at plan time, a Deny with conditions makes the effective access unclear, or the owning account is not known. |

## How to fix

Replace broad principals with explicit ARNs and add conditions that tie access to your organization or account. Use Block Public Access when you must block public bucket policies regardless of policy JSON.

- **AWS** (`aws_s3_bucket_policy`): Restrict `Principal` to specific IAM roles or accounts instead of `"*"`.

```hcl
resource "aws_s3_bucket_policy" "example" {
  bucket = aws_s3_bucket.example.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid       = "AllowPartnerRead"
      Effect    = "Allow"
      Principal = { AWS = "arn:aws:iam::111122223333:role/partner-read" }
      Action    = ["s3:GetObject", "s3:ListBucket"]
      Resource = [
        aws_s3_bucket.example.arn,
        "${aws_s3_bucket.example.arn}/*",
      ]
    }]
  })
}
```

- **AWS** (`aws_s3_bucket_public_access_block`): Block public bucket policies on this bucket.

```hcl
resource "aws_s3_bucket_public_access_block" "example" {
  bucket = aws_s3_bucket.example.id

  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}
```

- **AWS** (`aws_s3_bucket_policy`): When you must allow cross-account access, add `aws:SourceAccount` or `aws:PrincipalOrgID` so only your org or account can use the grant.

```hcl
resource "aws_s3_bucket_policy" "example" {
  bucket = aws_s3_bucket.example.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid       = "AllowOrgRead"
      Effect    = "Allow"
      Principal = "*"
      Action    = ["s3:GetObject"]
      Resource  = "${aws_s3_bucket.example.arn}/*"
      Condition = {
        StringEquals = {
          "aws:PrincipalOrgID" = "o-abc123def456"
        }
      }
    }]
  })
}
```

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-049
    address: aws_s3_bucket.uploads
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

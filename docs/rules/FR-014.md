# Object storage keeps prior versions

| | |
|---|---|
| **ID** | FR-014 |
| **Severity** | medium |
| **STRIDE** | Tampering, Denial of service |
| **Category** | Resilience |
| **Platforms** | AWS, Google Cloud, Cloudflare |

Available since Fray's first public release

## The risk

Overwriting an object drops the previous copy

## Why it matters

Overwriting the current object drops the previous copy. Versioning keeps that copy. Blocking destroy of the bucket is a separate control.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | Overwriting an object drops the previous copy. |
| **Mitigated** | The bucket keeps prior object versions. |
| **Unverified** | Fray could not tell whether versioning is on. Cloudflare R2 has no object versioning, so R2 buckets are always unverified for this rule. |

## How to fix

Enable versioning on the bucket.

On Cloudflare R2, object versioning is not available — use lifecycle rules or an external backup instead.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-014
    address: aws_s3_bucket.uploads
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

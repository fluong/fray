# NoSQL table is protected from deletion

| | |
|---|---|
| **ID** | FR-040 |
| **Severity** | medium |
| **STRIDE** | Tampering, Denial of service |
| **Category** | Resilience |
| **Platforms** | AWS |

Requires Action v0.34.0 or later.

## The risk

NoSQL table can be deleted through the cloud console or API

## Why it matters

Infrastructure-tool destroy guards do not stop console or API deletion. Without the provider deletion-protection flag, operators can drop the table and every workload that depends on it.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | Provider deletion protection is off, so the table can be deleted outside Terraform. |
| **Mitigated** | Provider deletion protection is on. |
| **Unverified** | Fray could not tell whether provider deletion protection is on. |

## How to fix

Enable deletion protection on the DynamoDB table. This is separate from `lifecycle.prevent_destroy`, which only blocks the infrastructure tool.

- **AWS** (`aws_dynamodb_table`): set `deletion_protection_enabled = true`.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-040
    address: aws_dynamodb_table.sessions
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

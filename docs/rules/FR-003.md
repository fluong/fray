# Credentials are not injected through the environment

| | |
|---|---|
| **ID** | FR-003 |
| **Severity** | low |
| **STRIDE** | Information disclosure |
| **Category** | Identity |
| **Platforms** | AWS, Google Cloud |

Available since Fray's first public release

## The risk

Secret is exposed in the process environment

## Why it matters

A secret in the environment is copied into crash dumps, debug endpoints, and child processes. A file mount is not.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | The secret is injected as an environment variable. |
| **Mitigated** | The secret is delivered as a mounted file. |
| **Unverified** | Fray only evaluates this rule when it can see how the secret is delivered, so it is never unverified. |

## How to fix

Deliver the secret as a mounted file. Do not put it in the process environment.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-003
    address: aws_iam_role.app -> aws_secretsmanager_secret.db credentials
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

# Database requires TLS for client connections

| | |
|---|---|
| **ID** | FR-031 |
| **Severity** | medium |
| **STRIDE** | Information disclosure |
| **Category** | Encryption |
| **Platforms** | AWS |

Available since 2026-10-12

For full results, use Fray Action v0.16.0 or later.

## The risk

Database accepts unencrypted client connections

## Why it matters

Without TLS on the database connection, credentials and query results can be read on the network path between the application and the database. See AWS RDS SSL/TLS for PostgreSQL (https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/PostgreSQL.Concepts.General.SSL.html) and Using SSL/TLS to encrypt a connection to a DB instance (https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/UsingWithRDS.SSL.html).

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | The database accepts unencrypted client connections. |
| **Mitigated** | The database rejects client connections that do not use TLS. |
| **Unverified** | Fray could not tell whether the database requires TLS: the parameter group is not visible in the plan, the engine's default is not assumed, or the scan came from a Fray Action older than v0.16.0. |

## How to fix

Require TLS for client connections on the database parameter group (rds.force_ssl for PostgreSQL, require_secure_transport for MySQL and MariaDB), or use an engine version whose documented default enforces TLS.

- **AWS** (`aws_db_parameter_group`): Set `rds.force_ssl = 1` (PostgreSQL) or `require_secure_transport = ON` (MySQL / MariaDB) on the DB parameter group.
- **AWS** (`aws_rds_cluster_parameter_group`): Set `rds.force_ssl = 1` (Aurora PostgreSQL) or `require_secure_transport = ON` (Aurora MySQL) on the cluster parameter group.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-031
    address: aws_db_parameter_group.main
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

# Secret use is scoped to one resource

| | |
|---|---|
| **ID** | FR-007 |
| **Severity** | medium |
| **STRIDE** | Elevation of privilege |
| **Category** | Identity |
| **Platforms** | AWS, Google Cloud |

For flow rules, Platforms lists the providers whose parsers produce the attributes this rule reads; the rule is evaluated on every matching flow, including flows to other providers (for example a Cloud Run service writing to a Cloudflare R2 bucket).

Available since Fray's first public release

## The risk

Secret access granted at project or account scope

## Why it matters

A grant wider than one secret lets the receiver read credentials it does not need.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | The caller can read every secret in the project or account. |
| **Mitigated** | The caller can read only this secret. |
| **Unverified** | Fray could not tell how wide the secret grant is. |

## How to fix

Grant access on the individual secret, not on the project or account.

- **AWS** (`aws_iam_policy`): scope `GetSecretValue` to the secret ARN in `Resource`, not `"*"`.
- **AWS** (`aws_iam_policy_document`): scope `GetSecretValue` to the secret ARN in `Resource`, not `"*"`.
- **Google Cloud** (`google_project_iam_member`): grant `roles/secretmanager.secretAccessor` on each secret with `google_secret_manager_secret_iam_member`, not on the project.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-007
    address: aws_iam_role.app -> aws_secretsmanager_secret.db credentials
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

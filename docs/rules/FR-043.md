# Cache is encrypted at rest

| | |
|---|---|
| **ID** | FR-043 |
| **Severity** | medium |
| **STRIDE** | Information disclosure |
| **Category** | Encryption |
| **Platforms** | AWS |

Requires Action v0.35.0 or later.

## The risk

Cache is not encrypted at rest

## Why it matters

Without at-rest encryption, snapshot and disk copies of the cache may be readable if storage is exposed. Encryption at rest is a baseline control for sensitive session or token data stored in Redis.

## How Fray evaluates it

Fray evaluates this rule on ElastiCache **Redis** elements when at-rest encryption settings are visible in the plan. **This rule is not evaluated for Memcached** — Memcached engines in the plan are skipped for FR-043.

| Result | Meaning |
|---|---|
| **Open** | The cache is not encrypted at rest (Redis). |
| **Mitigated** | The cache is encrypted at rest (Redis). |
| **Unverified** | Fray could not tell whether the cache is encrypted at rest (Redis). |

## How to fix

Enable at-rest encryption on the replication group.

- **AWS** (`aws_elasticache_replication_group`): Set `at_rest_encryption_enabled = true` for Redis.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-043
    address: aws_elasticache_replication_group.sessions
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

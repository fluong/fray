# LLM processing region is pinned

| | |
|---|---|
| **ID** | FR-017 |
| **Severity** | low |
| **STRIDE** | Information disclosure |
| **Category** | Data flow |
| **Platforms** | Google Cloud |

Available since Fray's first public release

## The risk

Model processing region is not pinned

## Why it matters

Customer content sent to a model is processed wherever that call is routed. A named region pins the call to one place. A missing region does not pin it, and global does not pin it either. Which regions an organization allows is a later policy, not this rule.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | Model calls are not pinned to one regional endpoint (missing or global). |
| **Mitigated** | Model calls are pinned to one regional endpoint. |
| **Unverified** | If no region is set, calls go to a global endpoint, so Fray reports this as open rather than unverified. |

## How to fix

Set the model region to a single regional endpoint, not global.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-017
    address: aws_s3_bucket.assets
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

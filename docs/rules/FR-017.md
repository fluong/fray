# LLM processing region is pinned

| | |
|---|---|
| **ID** | FR-017 |
| **Severity** | low |
| **STRIDE** | Information disclosure |
| **Category** | Data flow |
| **Platforms** | Google Cloud, AWS |

Available since Fray's first public release

## The risk

Model processing region is not pinned

## Why it matters

Customer content sent to a model is processed wherever that call is routed. On Google Cloud, a named region pins the call to one place. A missing region does not pin it (calls use the global endpoint), and global does not pin it either — both are reported as open. On AWS, Fray reads the processing region from Bedrock IAM grants when the Action reports it (same attachment resources as FR-004: `aws_iam_role_policy_attachment`, `aws_iam_policy_attachment` roles, and the `*_exclusive` IAM resources); if the region is unknown, the finding is unverified rather than open. Which regions an organization allows is a later policy, not this rule. AWS managed policies other than AmazonBedrockFullAccess are not read.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | Model calls are not pinned to one regional endpoint (missing or global on Google Cloud; global on AWS). |
| **Mitigated** | Model calls are pinned to one regional endpoint. |
| **Unverified** | On AWS, Fray could not tell which region model calls are processed in. |

## How to fix

Set the model region to a single regional endpoint, not global.

- **AWS** (`aws_iam_policy`): Grant `bedrock:InvokeModel` / `bedrock:InvokeModelWithResponseStream` only on foundation-model ARNs in one region; avoid `*` and geographic cross-region inference profiles if processing must stay in one region.
- **Google Cloud** (`google_cloud_run_v2_service`): Set a single regional Vertex endpoint (for example via `VERTEX_REGION`) and avoid the global endpoint.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-017
    address: aws_s3_bucket.assets
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

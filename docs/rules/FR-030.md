# Relational database is encrypted at rest

| | |
|---|---|
| **ID** | FR-030 |
| **Severity** | high |
| **STRIDE** | Information disclosure |
| **Category** | Encryption |
| **Platforms** | AWS, Google Cloud |

Available since 2026-10-11

## The risk

Relational database is not encrypted at rest

## Why it matters

A database without encryption at rest leaves stored customer data readable from volume snapshots and disk images.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | The database is not encrypted at rest. |
| **Mitigated** | The database is encrypted at rest. Cloud SQL always encrypts data at rest (Google-managed keys by default), so Cloud SQL instances are mitigated. |
| **Unverified** | Fray could not tell whether the database is encrypted at rest. |

## How to fix

Enable encryption at rest on the database.

- **AWS** (`aws_db_instance`): set `storage_encrypted = true` (must be set at creation).
- **Google Cloud** (`google_sql_database_instance`): Cloud SQL encrypts data at rest by default; use `encryption_key_name` for customer-managed keys if required.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-030
    address: aws_db_instance.main
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

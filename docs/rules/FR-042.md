# Cache transit encryption disabled

| | |
|---|---|
| **ID** | FR-042 |
| **Severity** | medium |
| **STRIDE** | Information disclosure |
| **Category** | Encryption |
| **Platforms** | AWS |

Requires Action v0.35.0 or later.

## The risk

Cache transit encryption disabled

## Why it matters

Without in-transit encryption, data moving between clients and the cache can be read on the VPC path. Redis and Memcached clients should use TLS when the engine supports it.

## How Fray evaluates it

Fray evaluates this rule on ElastiCache elements (`kind = cache`) for both Redis and Memcached when transit encryption settings are visible in the plan.

| Result | Meaning |
|---|---|
| **Open** | Transit encryption is off. |
| **Mitigated** | Transit encryption is on. |
| **Unverified** | Fray could not tell whether transit encryption is enabled. |

## How to fix

Enable transit encryption on the replication group or cluster.

- **AWS** (`aws_elasticache_replication_group`): Set `transit_encryption_enabled = true` (Redis). For Memcached, use the engine version and parameters that support in-transit encryption when available.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-042
    address: aws_elasticache_replication_group.sessions
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

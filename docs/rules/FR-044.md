# Queue or topic is not shared through its access policy

| | |
|---|---|
| **ID** | FR-044 |
| **Severity** | medium |
| **STRIDE** | Information disclosure, Elevation of privilege |
| **Category** | Exposure |
| **Platforms** | AWS |

Requires Action v0.38.0 or later.

Severity is **high** when the policy allows any principal. Severity is **medium** when the policy allows only specific principals outside this account.

## The risk

Queue or topic access policy grants access outside the account

## Why it matters

SQS queue policies and SNS topic policies can grant publish or consume access without going through IAM roles in your account. A policy that allows `*` or principals in other accounts lets callers outside your workload boundary send or receive messages if they satisfy the policy's conditions.

Fray evaluates **FR-044** on SQS queues and SNS topics in the plan (`kind = message_queue`).

## How Fray evaluates it

Fray evaluates this rule on every SQS queue and SNS topic in the plan.

| Result | Meaning |
|---|---|
| **Open** | The access policy allows any principal without a restricting condition, or allows a principal in another AWS account. |
| **Mitigated** | There is no resource policy, or the policy grants only principals in this account, or access is restricted by source owner, account, VPC, or source conditions that Fray can verify. An SNS topic with **no** policy resource in the plan uses the AWS default (owner only) and is mitigated. |
| **Unverified** | The policy could not be read at plan time, a Deny with conditions makes the effective access unclear, or the owning account is not known. |

## How to fix

Replace broad principals with explicit ARNs and add conditions that tie access to your organization or account.

- **AWS** (`aws_sqs_queue_policy`): Restrict `Principal` to specific IAM roles or accounts instead of `"*"`.

```hcl
resource "aws_sqs_queue_policy" "example" {
  queue_url = aws_sqs_queue.example.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid       = "AllowPartnerRole"
      Effect    = "Allow"
      Principal = { AWS = "arn:aws:iam::111122223333:role/partner-send" }
      Action    = ["sqs:SendMessage", "sqs:GetQueueAttributes"]
      Resource  = aws_sqs_queue.example.arn
    }]
  })
}
```

- **AWS** (`aws_sns_topic_policy`): When you must allow cross-account publish, scope `Principal` and add `aws:SourceAccount` or `aws:PrincipalOrgID`.

```hcl
resource "aws_sns_topic_policy" "example" {
  arn = aws_sns_topic.example.arn
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid       = "AllowOrgPublish"
      Effect    = "Allow"
      Principal = "*"
      Action    = ["sns:Publish"]
      Resource  = aws_sns_topic.example.arn
      Condition = {
        StringEquals = {
          "aws:PrincipalOrgID" = "o-abc123def456"
        }
      }
    }]
  })
}
```

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-044
    address: aws_sqs_queue.jobs
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

# Internet-reachable compute has a small instance cap

| | |
|---|---|
| **ID** | FR-002 |
| **Severity** | medium |
| **STRIDE** | Denial of service |
| **Category** | Resilience |
| **Platforms** | AWS, Google Cloud |

Available since Fray's first public release

## The risk

Internet-reachable service can grow without a tight cap

## Why it matters

An internet-reachable service can be driven up to its instance cap. Plan fidelity fills in provider defaults, so a cap that merely exists can be the default of 100. Ten or fewer bounds the cost. The cap does not keep the service available under load.

## How Fray evaluates it

| Result | Meaning |
|---|---|
| **Open** | The internet-reachable service can scale above ten instances. |
| **Mitigated** | The internet-reachable service is capped at ten instances or fewer. |
| **Unverified** | Fray could not tell what the instance cap is. |

## How to fix

Set the maximum instance count to 10 or fewer.

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-002
    address: aws_s3_bucket.assets
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```

# NoSQL table is not shared through its resource policy

| | |
|---|---|
| **ID** | FR-048 |
| **Severity** | medium |
| **STRIDE** | Information disclosure, Elevation of privilege |
| **Category** | Exposure |
| **Platforms** | AWS |

Requires Action v0.36.0 or later.

Severity is **high** when the policy allows any principal. Severity is **medium** when the policy allows only specific principals outside this account.

## The risk

NoSQL table resource policy grants access outside the account

## Why it matters

DynamoDB resource policies can grant data-plane access without going through IAM roles in your account. A policy that allows `*` or principals in other accounts lets callers outside your workload boundary read or write the table if they satisfy the policy's conditions.

## How Fray evaluates it

Fray evaluates this rule on DynamoDB table elements (`kind = nosql_db`) when a resource policy is present or explicitly absent in the plan.

| Result | Meaning |
|---|---|
| **Open** | The resource policy allows any principal without a restricting condition, or allows a principal in another AWS account. |
| **Mitigated** | There is no resource policy, or the policy grants only principals in this account, or access is restricted by organization, account, VPC, or source conditions that Fray can verify. |
| **Unverified** | The policy could not be read at plan time, a Deny with conditions makes the effective access unclear, or the owning account is not known. |

## How to fix

Replace broad principals with explicit ARNs and add conditions that tie access to your organization or account.

- **AWS** (`aws_dynamodb_resource_policy`): Restrict `Principal` to specific IAM roles or accounts instead of `"*"`.

```hcl
resource "aws_dynamodb_resource_policy" "example" {
  resource_arn = aws_dynamodb_table.example.arn
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid       = "AllowPartnerRole"
      Effect    = "Allow"
      Principal = { AWS = "arn:aws:iam::111122223333:role/partner-read" }
      Action    = ["dynamodb:GetItem", "dynamodb:Query"]
      Resource  = aws_dynamodb_table.example.arn
    }]
  })
}
```

- **AWS** (`aws_dynamodb_resource_policy`): When you must allow cross-account access, add `aws:SourceAccount` or `aws:PrincipalOrgID` so only your org or account can use the grant.

```hcl
resource "aws_dynamodb_resource_policy" "example" {
  resource_arn = aws_dynamodb_table.example.arn
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid       = "AllowOrgRead"
      Effect    = "Allow"
      Principal = "*"
      Action    = ["dynamodb:GetItem", "dynamodb:BatchGetItem"]
      Resource  = aws_dynamodb_table.example.arn
      Condition = {
        StringEquals = {
          "aws:PrincipalOrgID" = "o-abc123def456"
        }
      }
    }]
  })
}
```

## Waiving it

Add an entry to `.fray/waivers.yml`. Field limits and expiry horizons are in [Waivers](https://github.com/fluong/fray#waivers).
`address` is a Terraform resource address for an element finding, or `<from> -> <to> <data_class>` for a flow finding.

```yaml
version: 1
waivers:
  - id: waiver-1
    rule: FR-048
    address: aws_dynamodb_table.sessions
    reason: "Accepted risk; reviewed with the owning team."
    owner: "@security-eng"
    expires: "YYYY-MM-DD"
```
